# Clawpage Project Architecture & Prompt Expert Review

This document provides a comprehensive expert review of the recent architectural changes and prompt engineering patterns implemented in the `clawpage-skill` project.

## 1. Architectural Shift: The `npx` Runtime Migration
The recent migration to externalize execution via the `@clawpage.ai/cli` NPM package is a critical architectural improvement.

**Key Benefits:**
- **Context Window Optimization:** By removing all executable `.mjs` files from `scripts/` and HTML boilerplates from `templates/` out of the Git repository, the token payload consumed by the LLM is drastically reduced. The LLM only needs to process high-level prompt constraints (`SKILL.md`) without analyzing thousands of lines of shell, node scripts, and static HTML templates.
- **Separation of Concerns:** The plugin repository now strictly serves as a **declarative instruction set** for the LLM. The actual business logic (bundling, API communication, file scaffolding) is fully offloaded to the deterministic runtime (`@clawpage.ai/cli`).
- **Security & Sandboxing:** Transitioning away from directly executing raw local `.mjs` scripts prevents potential hallucination-driven modifications to the execution logic. Relying entirely on `npx -y @clawpage.ai/cli <command>` ensures the CLI tool executes predictably. Furthermore, the repository enforces a global workspace model (`~/.clawpage/pages/` or `./.pages/`), restricting generated output paths and treating the plugin installation directory as strictly read-only.

## 2. Browser SDK Introduction (`use-sdk`)
The introduction of `use-sdk/SKILL.md` profoundly shifts how interactive pages are generated by the LLM.

**Impact:**
- **Prompt Complexity Reduction:** Previously, adding persistent features (like comment boards, reactions, and file uploads) required the LLM to write repetitive `fetch()` boilerplate and manually handle Clawpage API error states. The SDK abstracts this entirely (e.g., `const c = new Clawpage(); c.table('reactions').incr(...)`).
- **Security:** The `use-sdk` prompt contract explicitly forbids hardcoding owner `sk_*` tokens into public pages. It enforces a strict boundary between public, token-less interactions and secure, CLI-side authenticated interactions.

## 3. Prompt Contracts and Sub-Skill Routing
The modular `SKILL.md` router pattern enables precise intent matching and structured code generation.

**Notable Patterns:**
- **Idempotency Guards:** The `create-page` and `update-page` sub-skills feature robust error-recovery mechanisms. By instructing the Agent to check the existence of `metadata.page_id` in the local `meta.md` following a network or server failure, the prompt prevents catastrophic data loss or duplicate page generation.
- **Anti-Generic-AI Checklists:** The inclusion of explicit negative constraints (e.g., "❌ Same font on every page", "❌ Cookie-cutter identical layout across pages") directly targets common LLM tendencies to converge on safe, bland designs. The system forces variation.
- **Localization Contracts:** Explicit guidelines around semantic placeholders (`__CONTENT_HTML__`, `__DEFAULT_CSS__`) versus LLM-rendered localized text ensure that the generated applications are both structurally sound and linguistically appropriate for the end-user.

## 4. Cross-CLI Compatibility
The project successfully expanded beyond Claude Code to support a broader ecosystem of AI Coding CLIs.

**Implementation:**
- **Claude Code:** Handled via `.claude-plugin/plugin.json` and `marketplace.json` for marketplace resolution.
- **Gemini CLI:** Supported via the `gemini-extension.json` shim.
- **Codex:** Compatible due to the flat-skill discovery pattern using a symlink (`SKILL.md` -> `skills/clawpage-skill/SKILL.md`).
- **OpenClaw:** Native support documented in `README.md` and `docs/README.zh-CN.md`.

**Conclusion:**
The shift from a "script-heavy plugin" to a "prompt-only declarative router" represents a best-in-class pattern for complex LLM tool development. The system effectively leverages the LLM's strengths (content generation, UI composition) while abstracting away its weaknesses (API boilerplate, build processes).
